微妙 · 加载体验提示词合集
==========================

核心原则：提前占位、持续反馈、即时响应、分阶段呈现。
UI：Logo 启动过渡、顶部进度条、骨架扫光、图片模糊到清晰。
UX：照片上传、乐观消息、叫车等待、分页预加载、AI 流式回复。
标签：UI / UX、平台、交互效果与视觉风格可组合。
每个案例包含一句话提示词、设计原则和五种独立可复制的完整提示词。
这是根据用户提供的九个场景整理的新提示词，不是原作者群内提示词。
浏览器演示使用本地模拟；小程序和 App 需按对应提示词另行实现原生组件。

01. [UI] Logo 开场，顺势入场
------------------------------------------------
归纳：让品牌标识变成入口，告别启动页到首页的生硬切换。
原则：用空间连续性连接两个状态
一句话提示词：让 Logo 放大淡出，首页像幕布打开一样从下方浮现，等待和进入保持连贯。

【PC / Web · 完整提示词开始】

目标：Logo 开场，顺势入场。让 Logo 放大淡出，首页像幕布打开一样从下方浮现，等待和进入保持连贯。

使用场景：内容型应用从启动页进入首页；仅在应用内展示过渡，不模拟或替换操作系统启动屏。

风格方向：极简、品牌感。启动层使用深森林色 #222b20，方形 Logo 使用青柠色 #d0ff6c 与真实 Layers SVG；首页使用浅色背景。Logo 圆角 16px，避免文字字符充当图标。 使用清晰层次、充足留白与统一间距；图标使用真实 SVG 组件，不用文字或 Emoji 代替。

结构与交互：设计一段应用内启动过渡。初始为深森林色 #222b20 背景与青柠色 #d0ff6c 方形品牌 Logo，旁边有“正在准备你的灵感”状态文字。点击“进入首页”后保留启动画面至内容准备结束；结束前最后 30% 的时间里，将 Logo 从 1 倍放大到 12 倍并逐渐淡出，首页从下方 24px 淡入，使用 cubic-bezier(.22,1,.36,1)。首页包含“今天，也有新灵感”、三张色彩卡和一条内容摘要。整个过程中内容容器尺寸固定，过渡层不阻止完成后的操作。失败时保留品牌与错误说明，提供重试，不进入空首页。减少动态效果模式使用直接切换和状态文字。

当前演示参数：一次模拟任务总时长 2400ms；默认成功，同时保留可切换的失败演示。时间仅用于本地模拟；生产环境不能用定时器假装真实完成。

目标端：PC / Web。使用 React + TypeScript + CSS，语义化 DOM；桌面内容最大宽度 1200px，兼容 375px 以上布局。用浏览器请求或事件驱动真实状态，演示不得依赖后台服务。

无障碍：所有按钮支持键盘操作并有可见焦点；异步状态使用简短文字播报，不能只依赖颜色；遵循系统减少动态效果设置，移除非必要位移与循环动画，保留状态反馈。

实现边界：启动动画不会提升首屏数据速度。真实项目要先完成必要初始化，再推进到首页；不要人为延迟可用内容。

验收标准：
1. 启动后能到达首页，重播可回到启动页
2. 模拟失败停留在错误状态并能重试
3. 减少动态效果时仍能进入首页

【完整提示词结束】

02. [UI] 轻量顶部进度条
------------------------------------------------
归纳：原页面保持可见，用一条细线交代导航正在发生。
原则：轻反馈，不打断当前上下文
一句话提示词：页面不动，顶部 3px 进度条先快后慢推进，请求完成才冲到终点并淡出。

【PC / Web · 完整提示词开始】

目标：轻量顶部进度条。页面不动，顶部 3px 进度条先快后慢推进，请求完成才冲到终点并淡出。

使用场景：切换内容页或刷新已有数据，不适合阻塞性或破坏性操作。

风格方向：极简、浅色。原内容使用奶油白 #fffef5、深灰绿正文和低饱和色块；顶部 3px 导航线使用 #658b60。信息层级克制，保持阅读区域稳定。 使用清晰层次、充足留白与统一间距；图标使用真实 SVG 组件，不用文字或 Emoji 代替。

结构与交互：实现一个页面顶部 3px 的绿色导航进度条。点击“刷新内容”保留现有文章、标题和卡片；进度条按先快后慢的曲线从 0 推进，未收到完成信号前最多到 90%。请求成功后到 100%，停留 250ms 后用 200ms 淡出，文字更新为“内容已更新”。这是不确定进度指示，不展示假百分比。失败时进度条停下并改用文字“刷新失败，原内容仍可查看”，提供重试。运行时禁用重复刷新，组件销毁时清理所有资源；采用 transform: scaleX 且原点在左侧。减少动态效果时显示静态加载线与状态文字。

当前演示参数：一次模拟任务总时长 3000ms；默认成功，同时保留可切换的失败演示。时间仅用于本地模拟；生产环境不能用定时器假装真实完成。

目标端：PC / Web。使用 React + TypeScript + CSS，语义化 DOM；桌面内容最大宽度 1200px，兼容 375px 以上布局。用浏览器请求或事件驱动真实状态，演示不得依赖后台服务。

无障碍：所有按钮支持键盘操作并有可见焦点；异步状态使用简短文字播报，不能只依赖颜色；遵循系统减少动态效果设置，移除非必要位移与循环动画，保留状态反馈。

实现边界：这是模拟导航指示，不是真实下载百分比。实际项目由路由或请求完成事件驱动收尾。

验收标准：
1. 请求未完成时进度不超过 90%
2. 成功后完成并淡出，原页面始终可见
3. 失败后可重试且保留原内容

【完整提示词结束】

03. [UI] 骨架扫光，内容接力
------------------------------------------------
归纳：先把内容的位置留好，数据到达后再逐块揭晓。
原则：先交代结构，再填充内容
一句话提示词：用与内容同尺寸的骨架占位，轻柔扫光，完成后按块错开 90ms 浮现。

【PC / Web · 完整提示词开始】

目标：骨架扫光，内容接力。用与内容同尺寸的骨架占位，轻柔扫光，完成后按块错开 90ms 浮现。

使用场景：文章和卡片列表首次加载，已知内容结构但数据尚未返回。

风格方向：编辑式、浅色。采用编辑式纸张布局，底色 #f0eae0、石灰色占位与深色标题；图片和文字占位的尺寸与最终内容严格对齐。 使用清晰层次、充足留白与统一间距；图标使用真实 SVG 组件，不用文字或 Emoji 代替。

结构与交互：实现一个三行灵感文章列表的加载效果。每行使用固定尺寸的封面、两行标题占位和一行辅助信息，骨架结构与最终内容完全一致。点击“加载内容”后先显示低对比度灰色骨架，以 1.5s 周期从左向右扫光；数据到达时停止扫光，三行以 90ms 间隔从下方 8px 淡入，每行过渡 320ms。内容为“让空间保持呼吸”“把日常装进设计”“收集微小的美好”。失败时停止循环动画并展示可重试的错误状态，不能让骨架无限播放。减少动态效果时骨架静止、内容直接替换。

当前演示参数：一次模拟任务总时长 2600ms；默认成功，同时保留可切换的失败演示。时间仅用于本地模拟；生产环境不能用定时器假装真实完成。

目标端：PC / Web。使用 React + TypeScript + CSS，语义化 DOM；桌面内容最大宽度 1200px，兼容 375px 以上布局。用浏览器请求或事件驱动真实状态，演示不得依赖后台服务。

无障碍：所有按钮支持键盘操作并有可见焦点；异步状态使用简短文字播报，不能只依赖颜色；遵循系统减少动态效果设置，移除非必要位移与循环动画，保留状态反馈。

实现边界：占位尺寸要按真实内容布局预留。真实数据未就绪时不能为结束动画而展示虚构内容。

验收标准：
1. 骨架与内容高度一致
2. 成功时三行有顺序地出现
3. 失败时停止扫光并出现重试入口

06. [UX] 消息先到，状态跟上
------------------------------------------------
归纳：发送即上屏，把“等服务器”变成可理解的状态。
原则：立即回应操作，诚实交代结果
一句话提示词：发送后立刻插入消息并标记发送中，确认后显示双勾，失败保留内容并可重试。

【PC / Web · 完整提示词开始】

目标：消息先到，状态跟上。发送后立刻插入消息并标记发送中，确认后显示双勾，失败保留内容并可重试。

使用场景：即时聊天或评论发送；不适合支付等需要强一致确认的操作。

风格方向：柔和、圆角。采用柔和浅粉色 #fcf5f7 和圆角气泡，接收气泡中性浅色、发送气泡深绿色；发送中用 Clock、送达用 CheckCheck、失败用 CircleAlert SVG 图标。 使用清晰层次、充足留白与统一间距；图标使用真实 SVG 组件，不用文字或 Emoji 代替。

结构与交互：实现聊天中的乐观发送。提供输入框和“发送消息”按钮，拒绝空白内容，最多 120 字。点击后立即把文本插入右侧绿色气泡，清空输入，显示“发送中”；模拟确认后同一条消息显示双勾与“已送达”，不能重复插入。双勾仅代表送达，不虚构已读。模拟失败后保留原消息并标记“发送失败”，允许针对同一消息重试；不要求用户重新输入。演示限制同一时间一个待确认任务，重复点击不能重复发送。生产环境为每条消息生成稳定客户端 ID，服务端按幂等键去重，重试沿用原 ID。状态变化可被辅助技术理解，焦点留在输入区域。

当前演示参数：一次模拟任务总时长 2400ms；默认成功，同时保留可切换的失败演示。时间仅用于本地模拟；生产环境不能用定时器假装真实完成。

目标端：PC / Web。使用 React + TypeScript + CSS，语义化 DOM；桌面内容最大宽度 1200px，兼容 375px 以上布局。用浏览器请求或事件驱动真实状态，演示不得依赖后台服务。

无障碍：所有按钮支持键盘操作并有可见焦点；异步状态使用简短文字播报，不能只依赖颜色；遵循系统减少动态效果设置，移除非必要位移与循环动画，保留状态反馈。

实现边界：乐观更新缩短感知等待，不代表发送成功。真实系统需要幂等键、网络确认、超时与断线重连策略。

验收标准：
1. 点击后无需等待即可看到原文本
2. 失败不丢失消息，重试不新增重复气泡
3. 成功显示送达，空白文本不可发送
